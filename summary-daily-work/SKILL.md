# summary-daily-work · 工作日报

简要指令：`summary-daily-work`（等同于「工作日报 / 今日日报」）。

将当前会话与仓库中的**真实进展**整理为可直接粘贴的六段式日报。读完本 Skill 后先收集证据再输出，不要先追问无关细节。

## 工作流

1. **确定范围**
   - 默认：当前对话 + **今日**（本地时区）git 活动
   - 用户指定日期时，按该日范围执行

2. **收集证据**（按需并行）
   - 对话：目标、决策、未完成项
   - Git：父仓与子模块分别 `status` / `log --since=今日` / `diff --stat`
   - 未提交改动标注「本地未提交」

3. **归类填槽**（见下方模板与填写要点）

4. **输出**
   - 默认只输出六段可复制块（`text` 代码块）
   - **六段标题一字不改**

## 输出模板（必须原样使用这些标题）

```text
【目标】
1. 
2. 

【已完成工作】
1. 
2. 

【解决的问题】
1. 
2. 

【剩余问题】
1. 
2. 

【总结】

【下一步建议】
1. 
2. 
```

## 填写要点

| 段 | 填什么 |
|----|--------|
| 目标 | 今日要达成的业务/技术目标；可含里程碑（如 P0/P1、V1.1） |
| 已完成工作 | 可验证交付：功能、修复、文档、测试、部署；动词开头、编号罗列 |
| 解决的问题 | 「问题 → 处理」；写清障碍与已采取措施 |
| 剩余问题 | 未提交、未验收、阻塞、风险；无则写「暂无。」 |
| 总结 | 1–2 句：进展评价 + 价值（**不要**把行动项写在这里） |
| 下一步建议 | 可执行的后续动作，编号罗列；承接剩余问题，写清优先级或顺序 |

## 质量门禁

- 六段标题不得改动；不得整段省略（无内容写「暂无。」或「待补充：…」）。
- 已完成工作、剩余问题、下一步建议各至少 1 条（明确无项除外）。
- **不得编造**未见过的提交、功能、问题或数据。
- 未提交改动必须标注「本地未提交」。
- 含子模块时注明归属（如父仓 `doc/`、子模块 `src/`）。
- 「总结」与「下一步建议」分工：总结只评价，行动项只放下一步建议。
- 全文简体中文；简洁，不堆 commit hash。

## 证据优先级

1. 用户明确陈述的目标与结论  
2. 当前会话中的实现与验证结果  
3. Git 提交与 diff  
4. 项目文档（doc、README、方案）  
5. 禁止仅凭旧记忆填充  

## 示例（已填充示意）

2. 编写 scripts/generate_codegraph.py，生成并落入 doc/24-项目结构图示-CodeGraph.md 与 doc/_codegraph/（HTML/CSV/摘要）。

4. 落地 P1：HTTP Form/JSON 客户端、任务 incremental|backfill 分离、ggzy 政采/工程分频道与 Form 优先。
5. 同步 API/调度入队载荷、sources.json 字段、doc17/25/README；新增 matcher/portal/pipeline 单测（本地未提交）。

【解决的问题】

【总结】
今日完成「策略竞品 → 结构图示 → P0/P1 采集链路改造」闭环，核心价值是控详情流量与提高过滤精度。

1. 提交父仓 doc/scripts 与子模块 src 变更并合入主干。
2. 单源联调（ccgp/ggzy）验证列表预筛、回填 mode 与 Form 回退。
